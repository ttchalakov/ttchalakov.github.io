# CLAUDE.md

Personal research website for Teodor Tchalakov, served at https://ttchalakov.github.io. It is a user site, so `baseurl` stays empty. It is built on the al-folio v1.2 Jekyll starter (upstream commit `fde4cbf`). README.md has the content map and the publishing steps.

## How the site is put together

- al-folio v1 is a thin starter. Layouts, includes, Sass, and JS live in the `al_*` gems pinned in the `Gemfile`, installed under `vendor/bundle/ruby/3.3.0/gems/`. To learn what a front-matter or config key does, read the gem source there (start with `al_folio_core-*/_layouts/` and `_includes/`). Override a gem file by copying it to the same path in this repo, and only when config or content can't do the job.
- The image viewer is a gem override too: `_includes/plugins/al_img_tools_scripts.liquid` and `al_img_tools_styles.liquid` (al_folio_core's wrappers for the al_img_tools tags) add PhotoSwipe 5.4.4. It opens any `data-zoomable` image (the paper images) full screen, with wheel, click, and pinch zoom and drag to pan. `enable_medium_zoom` is false because medium-zoom only scaled to the window, let the fixed navbar and footer cover tall images, and couldn't zoom further. When upgrading al_img_tools, keep the PhotoSwipe version and integrity hash in step with its pins.
- The main style override is `assets/css/main.scss`. It differs from `al_folio_core`'s copy in three ways. It sets the accent color: `$purple-color` (light theme, `#245b99`) and `$cyan-color` (dark theme, `#4c87cb`), both deep blues picked to meet WCAG link contrast against the background and the body text. And a rule at the end makes the whole name bold (the theme bolds only the first name) in the home page title and the navbar. A second rule widens the paper-image column in publication lists from about 125 px to about 240 px (30% of the content, with the text in the other 70%), because the theme's thumbnails were too small to read. Re-sync it with the gem's file when upgrading `al_folio_core`.
- Any top-level folder not starting with `_` or `.` is copied into the published site unless it is listed under `exclude:` in `_config.yml`. Add new non-site folders there.
- A plugin must be listed in both the `Gemfile` and `plugins:` in `_config.yml`. A plugin listed in only one does nothing and reports no error.
- `protect_email: true` does not protect the home-page email icon in this version: `{% social_links %}` (jekyll-socials) prints a plain `mailto:`, and `al_email_protect`'s rewrite filter puts other attributes inside `class="..."`, which produces malformed HTML. It is left `false`.
- Publishing policy (Teodor's standing instruction): when he asks to publish or deploy, Claude commits and pushes itself, always with `bin/publish.sh "message"`. It replaces `main` with one commit of the current files and force-pushes, and the deploy keeps `gh-pages` to one commit (`single-commit: true`). That way a removed email or photo doesn't survive in the repository's history. Never push ordinary commits on top of history. Force-pushing hides old versions from the branch and commit views, but GitHub can still serve old commits by their ID, and the repository's Activity page lists force pushes. For something truly sensitive, also delete and recreate the repository or ask GitHub Support to purge it.
- Pushing to `main` runs `.github/workflows/deploy.yml`, which builds `_site` and pushes it to the `gh-pages` branch that Pages serves. Never commit to `gh-pages` directly. Every push to `main` deploys; the workflow has no `paths:` filter on push, because publishes are single commits with no shared history, which a path filter can't compare. It can also be run by hand from the Actions tab.
- Publications come in three kinds. Peer-reviewed papers are `@article` and `@inproceedings` entries in `_bibliography/papers.bib`. Papers under review are `@unpublished` entries listed first with an "Under review" badge: while a double-blind venue reviews a paper, the site shows its title, authors, abstract, and a figure, but no venue, PDF, or BibTeX. Working papers (the RISS reports) are `@techreport` entries with a `howpublished` venue, which `_includes/hook/bib.liquid` (a hook the theme's bib layout provides) shows as the italic venue line. The home page lists both groups in full at the end of `_pages/about.md` (its `selected_papers` setting is off, and the `selected` field in `papers.bib` is no longer used), and `_pages/publications.md` queries them as separate sections. Never type an at sign in a `papers.bib` comment: BibTeX reads it as the start of an entry and silently drops the next real one.
- `robots.txt` blocks crawlers that collect pages for AI training or AI datasets (78 of them, chosen from the ai.robots.txt list) and leaves search engines, AI search, user-triggered assistant fetches, and link previews allowed.

## Commands

- Ruby comes from Homebrew's keg-only `ruby@3.3`: `export PATH="/opt/homebrew/opt/ruby@3.3/bin:$PATH"`. The macOS system Ruby (2.6) is too old.
- `./start.sh` runs the preview at http://localhost:4000 in the background (PID and log in `tmp/`, which is gitignored and excluded from the build); `./stop.sh` stops it. Restart after editing `_config.yml`. If ImageMagick's `convert` is missing, `start.sh` turns off responsive-image generation.
- Production-like build: `JEKYLL_ENV=production bundle exec jekyll build`.
- Formatting: `npm ci`, then `npx prettier . --check` (or `--write`).

## Content rules

- Never invent publications, CV entries, affiliations, or biography details. Use only what Teodor provides. Scaffold placeholders are marked TODO, Example, or PLACEHOLDER.
- Source material: `old_resumes/` holds Teodor's 2023 and 2026 resumes (Word files; extract text with `textutil -convert txt`, and the contact header with `unzip -p <file> word/header1.xml`). The bio, projects, and socials were filled from them (a CV page was too, then removed at Teodor's request: the site has no CV page, and the home page's Background list covers it), with publication metadata from the arXiv, Crossref, and workshop-page links in the 2026 resume. The folder is gitignored and excluded from the build because the resumes contain a phone number. Keep the phone number and home city off the site.
- Don't host paper PDFs on the site; link to where each paper is published. The one exception is the ICRA 2022 workshop paper (`assets/pdf/autompc_icra2022_workshop.pdf`), because the workshop's own copy is gone. The RISS 2022 working paper links to page 211 of that year's RISS Working Papers Journal (the journals are listed at https://riss.ri.cmu.edu/research_showcase/working-papers-journals/). No 2024 journal exists, so the 2024 paper links to Teodor's Google Drive copy. Both have Poster (Drive) and Video (YouTube) buttons.
- Images go in `assets/img/`, with project media in `assets/img/projects/<project>/`. Videos go in `assets/video/` as small H.264 MP4 files.
- The profile photo, `assets/img/profile/prof_pic.webp`, is made with `bin/cloak_photo.sh --no-cloak` (see README), which strips the metadata (phone photos carry GPS), crops, and converts to WebP. The script can also add a face-recognition cloak, but Teodor rejected it for the current photo. At the default strength it stopped 6 of the 7 test models but looked uncanny up close, and versions too faint to notice stopped none. Don't add one without showing them the before-and-after image. A cloaked photo must stay WebP, because the build's ImageMagick step re-encodes JPEG and PNG into resized copies. Never commit or publish an original photo; `*.heic` is gitignored and build-excluded. The script installs its packages and models in temporary folders on each run, so don't install them into `.venv/`.
- Use `.venv/` (gitignored, Python 3.13) for scripted image and video work; ffmpeg is installed. Keep generator scripts out of the Jekyll build by adding their folder to `exclude:` in `_config.yml`.
